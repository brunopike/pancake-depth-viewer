# ESIM 链上报告

统一入口为 `https://starkweng.github.io/esim-onchain/`，默认显示链上报告，`?view=addresses` 显示卖出地址，`?view=depth` 显示买卖深度。三个视图复用原仓库页面、数据和 API；配色统一为深色，卖出红色、买入绿色、选中金色。当前页导航为禁用按钮，其余入口在新标签页打开。原 `pancake-depth-viewer/` 与 `onchain-report/` 继续可用。Alchemy Key 只配置在 GitHub Actions Secret 和 Vercel 的 Production 环境变量 `ALCHEMY_API_KEY`，不要放进网页、URL 或前端构建变量。

## 统计口径

- 今日：北京时间 00:00 到已核验区块；昨日：前一个完整自然日；历史：2026-10-03 09:59:50 起。
- 时段含起点、不含终点。金额以整数 wei 累加，显示时才四舍五入。地址和交易按集合去重。
- 曾领币地址必须在交易发生前已从指定分发合约领币。同一交易里的买、卖分别统计；复杂路径保留未归因，不把路由器当交易者。
- 覆盖登记并核验的 ESIM 池，不含 CEX。页面显示池子数量及截止区块，不把它宣称为全市场所有交易。
- BNB 直接入金、内部入金、全量支出分别统计，必须与前后链上余额相符。失败的调用和内部回滚不计入。
- 首次历史底稿来自既有核验记录；后续增量校验交易回执、区块哈希、日志、买卖总量与 BNB 余额。未通过就保留上一份记录。

## 刷新与费用边界

浏览器首次打开读取缓存，不触发付费历史扫描。手动刷新通过 Vercel `/api/esim` 查询新增交易；本接口只支持固定 ESIM 和分发合约，不接受 RPC 方法或上游 URL 参数。余额接口仅接受已核验交易数据中的地址，每次最多 25 个。

Vercel 单次最多 300 个 HTTP 批次、225 秒；普通批次最多 40 个 RPC 请求，重型日志/trace 批次最多 6 个。一个实例同一时刻只运行一次更新，完成后 60 秒内复用结果。它是实例内限频，不是跨实例的全局配额。部署平台的访问限制应根据实际公开访问量另行设置。

GitHub 工作流 `Refresh ESIM report` 每小时运行一次，只补查 ESIM；保存到 `esim-cache` 分支。GitHub 定时任务可能延迟，页面始终以实际核验截止时间为准。后台单次最多 600 个 HTTP 批次、25 分钟，30 分钟工作流上限；中途失败也只发布已经完成核验的区段。

Vercel 每次开始付费刷新前加载最新保存点；中断、重启或后台较长时间未更新时分段追赶。页面会明确显示“补齐较长时间的间隔”，不会把部分追赶标成最新数据。该刷新不涉及签名、转币或交易。

## 部署

1. GitHub 仓库保留现有 Pages 工作流，发布 `dist`；原深度首页继续可用。
2. Vercel 导入同一仓库，Application Preset 为 Other，根目录为 `./`。`vercel.json` 设置 `npm run build` 和 `dist`，并部署 Node 查询接口。
3. 配置敏感的 Production 环境变量 `ALCHEMY_API_KEY`。不需要前端 Key 或 GitHub 管理令牌。
4. 将 Vercel 正式域名写入 `public/data/esim-config.json` 的 `apiOrigin`，供 GitHub Pages 调用；Vercel 同站页面可直接调用同源接口。
5. 手动运行一次 `Refresh ESIM report`，确认 `esim-cache/report.json` 的区块和时间推进。浏览器再点击刷新，核对接口结果和页面时间。

## 验证

`npm test` 包含北京时间边界、同笔买卖、地址去重、实际交易回执回归、BNB 余额、请求预算、接口来源与输入限制。`npm run build` 生成两个独立页面。上线验收必须另做浏览器实际刷新，不能只以构建或工作流配置作为完成依据。

运行本地预览：`node scripts/esim/preview.mjs`，访问 `http://127.0.0.1:4317/esim.html`。未配置服务端 Key 时，刷新会提示未配置并保留旧数据。

## 卖出地址页

`/esim-addresses.html` 提供今日、昨日、历史排名；可筛我方、领过币、其他交易和高频，支持地址搜索和 BscScan 跳转。交易发起地址与出币资金地址分别排名。

我方刷量按用户指定的执行合约 `0x21a0541e4122090c30fbc04e98cf27430608e007` 识别；使用该合约的交易发起地址动态加入，不固定限制为原有 200 个。我方 LP 沿用两个已提供的钱包。高频指所选时段内任一北京时间自然日达到 100 笔交易，标签可以重叠，单纯高频不会推断归属。

排名接口每页只返回 25 条，防止历史增长超过托管平台响应大小。余额查询仅覆盖当前页，在同一固定区块读取 ESIM、USDT 与 BNB，复核区块哈希并缓存 60 秒。USDT 余额是链上持有量，并非 ESIM 的估值 U。
