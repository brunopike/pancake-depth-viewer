# ESIM 链上报告

统一入口为 `https://starkweng.github.io/esim-onchain/`，默认显示链上报告，`?view=addresses` 显示卖出地址，`?view=depth` 显示买卖深度，`?view=holders` 显示持币地址。四个视图复用原仓库页面、数据和 API；配色统一为深色，卖出红色、买入绿色、选中金色。导航为横向标签栏，当前页金色下划线且不可点击；刷新按钮沿用深度页样式。当前页导航为禁用按钮，其余入口在新标签页打开。原 `pancake-depth-viewer/` 与 `onchain-report/` 继续可用。Alchemy Key 只配置在 GitHub Actions Secret 和 Vercel 的 Production 环境变量 `ALCHEMY_API_KEY`，不要放进网页、URL 或前端构建变量。

## 统计口径

- 今日：北京时间 00:00 到已核验区块；昨日：前一个完整自然日；历史：2026-10-03 09:59:50 起。
- 时段含起点、不含终点。金额以整数 wei 累加，显示时才四舍五入。地址和交易按集合去重。
- 曾领币地址必须在交易发生前已从指定分发合约领币。同一交易里的买、卖分别统计；复杂路径保留未归因，不把路由器当交易者。
- 覆盖登记并核验的 ESIM 池，不含 CEX。页面显示池子数量及截止区块，不把它宣称为全市场所有交易。
- BNB 直接入金、内部入金、全量支出分别统计，必须与前后链上余额相符。失败的调用和内部回滚不计入。
- 首次历史底稿来自既有核验记录；后续增量校验交易回执、区块哈希、日志、买卖总量与 BNB 余额。未通过就保留上一份记录。

## 刷新与费用边界

浏览器首次打开读取缓存，不触发付费历史扫描。手动刷新通过 Vercel `/api/esim` 查询新增交易；本接口只支持固定 ESIM 和分发合约，不接受 RPC 方法或上游 URL 参数。余额接口仅接受已核验交易数据中的地址，每次最多 25 个。

Vercel 单次最多 300 个 HTTP 批次、225 秒；普通批次最多 40 个 RPC 请求，重型日志/trace 批次最多 6 个。一个实例同一时刻只运行一次更新，完成后 60 秒内复用结果。它是实例内限频，不是跨实例的全局配额。部署平台的访问限制应根据实际公开访问量另行设置。

GitHub 工作流 `Refresh ESIM report` 每小时运行一次，只补查 ESIM；保存到 `esim-cache` 分支。GitHub 定时任务可能延迟，页面始终以实际核验截止时间为准。后台单次最多 600 个 HTTP 批次、25 分钟，30 分钟工作流上限；中途失败也只发布已经完成核验的区段。

Vercel 每次开始付费刷新前加载最新保存点；中断、重启或后台较长时间未更新时分段追赶。页面会明确显示“补齐较长时间的间隔”，不会把部分追赶标成最新数据。该刷新不涉及签名、转币或交易。

## 部署

1. GitHub 仓库保留现有 Pages 工作流，发布 `dist`；原深度首页继续可用。
2. Vercel 导入同一仓库，Application Preset 为 Other，根目录为 `./`。`vercel.json` 设置 `npm run build` 和 `dist`，并部署 Node 查询接口。
3. 配置敏感的 Production 环境变量 `ALCHEMY_API_KEY`。不需要前端 Key 或 GitHub 管理令牌。
4. 将 Vercel 正式域名写入 `public/data/esim-config.json` 的 `apiOrigin`，供 GitHub Pages 调用；Vercel 同站页面可直接调用同源接口。
5. 手动运行一次 `Refresh ESIM report`，确认 `esim-cache/report.json` 的区块和时间推进。浏览器再点击刷新，核对接口结果和页面时间。

## 验证

`npm test` 包含北京时间边界、同笔买卖、地址去重、实际交易回执回归、BNB 余额、请求预算、接口来源与输入限制。`npm run build` 生成四个独立页面。上线验收必须另做浏览器实际刷新，不能只以构建或工作流配置作为完成依据。

运行本地预览：`node scripts/esim/preview.mjs`，访问 `http://127.0.0.1:4317/esim.html`。未配置服务端 Key 时，刷新会提示未配置并保留旧数据。

## 卖出地址页

`/esim-addresses.html` 提供今日、昨日、历史排名；可筛我方、领过币、其他交易和高频，支持地址搜索和 BscScan 跳转。交易发起地址与出币资金地址分别排名。

我方刷量按用户指定的执行合约 `0x21a0541e4122090c30fbc04e98cf27430608e007` 识别；使用该合约的交易发起地址动态加入，不固定限制为原有 200 个。我方 LP 使用用户已确认的四个地址。高频指所选时段内任一北京时间自然日达到 100 笔交易，标签可以重叠，单纯高频不会推断归属。

排名接口每页只返回 25 条，防止历史增长超过托管平台响应大小。余额查询仅覆盖当前页，在同一固定区块读取 ESIM、USDT 与 BNB，复核区块哈希并缓存 60 秒。USDT 余额是链上持有量，并非 ESIM 的估值 U。


## 持币地址页

`?view=holders`（原地址 `/esim-holders.html`）按 ESIM 钱包余额降序，默认 100 个地址一页。支持多选标签（符合任意一项，清空即全部）、搜索、BscScan 链接，以及标签持仓占比 / 前 10 地址图表；前十按持币量编号 1–10。币量和估值固定显示两位小数，交易次数为整数，原始数据精度不变。我方、我方 LP、我方执行地址不再显示高频或套利机器人标签。手动标签保存在当前浏览器，编辑与删除均须先核对再确认，公开标签仍保留。

- 名单来自 OKLink 可见前 1000、用户 Excel 的 33 个地址标签、已知收币/交易/交互地址及新增 ESIM Transfer 参与者；不是全链完整持有人名单。页面显示已索引数及覆盖供应量。
- 当前余额、总供应量与价格采用同一固定区块，24h 余额按不晚于 24 小时前的区块读取。历史余额失败显示暂缺。钱包价值采用同区块 Pancake 现价，仅作参考。
- LP 标签包含 `0x1db99241d9e230edc33996567ec2707c42475fd8`、`0xc40409aee5b913f14dfd8f967299ddf9dc5009a1`、`0x23dd01612443d15c166aed7b430abdaeef923783`、`0xdcdb497a0b2ab74753f8e40e36071ce7a0ab4930`。此处显示钱包余额，不含池内 LP 仓位。
- 买卖次数按发起地址和交易哈希去重，买卖两边分别计数；数额以 ESIM 成交币量展示，不用现价冒充历史 USDT 成交额。交易 24h 以交易底稿截止时间倒推，和余额时间分别显示。累计自 2026-10-03 09:59:50 开始。
- `src/holder-labels.mjs` 统一保存用户确认的三个合约标签，网页旧快照和后台后续报告共用；不据此将调用它们的所有钱包判为我方。
- 自动识别的高频机器人为疑似标签：任一北京时间自然日达到 100 笔；套利疑似至少 3 笔同笔双向买卖，均不证明身份或利润。领币后卖出要求领取先于卖出；当前清仓要求当前余额恰为零，但归零也可由转出造成。
- 每个地址在分组图中只计一次；多标签优先 LP、我方、交易所托管、DEX、领币、高频/套利、合约、其他。交易所用户地址不当作交易所自有资产。手动分类优先用于本机图表。

GitHub `Refresh ESIM holders` 每小时仅查询 ESIM（分钟 49，实际执行可能延迟），写入 `holder-cache/holders.json`。网页“更新快照”读取这个静态结果，不触发付费扫描。`GET /api/holders` 重定向至固定快照，避免大名单超过函数响应大小；POST 禁止。首次只发现最近 24h ESIM 转账参与者，以后增量追加，历史静止小户并未完整补齐。
